# تنظيم أعمال الدائرة الرابعة — الإصدار الثاني

موقع مستقل يعمل على **GitHub Pages** دون Lovable، مستوحى بصريًا من شكل البوابات الإدارية السعودية من حيث الأخضر والأبيض والتبويبات والبطاقات، **دون أي شعار أو ادعاء ارتباط بوزارة أو جهة حكومية**.

## أهم الميزات

### 1) القضايا ومحاضر الجلسات
- جدول قضايا اليوم التالي مع اختيار التاريخ، وبيانات الدعوى والأطراف ورقم القضية والوقت.
- إدراج نص ضبط الجلسة السابقة كاملًا، وملخص الجلسة، وسبب الرفع، واقتباس حرفي يدعم السبب؛ الاقتباس يجب أن يطابق المحضر قبل الحفظ.
- إضافة وتعديل وإزالة القضايا، بما فيها القضايا التي تضاف بعد الحصر الأولي.
- إظهار اسم من أدخل القضية، وآخر من عدلها، وسجل التغييرات في قاعدة البيانات.
- القاضي يراجع ملخص كل قضية ويعتمدها؛ أي تغيير في بيانات القضية يلغي اعتمادها.
- صفحة «تقرير الجلسات» مع **اعتماد التقرير اليومي** بعد اعتماد جميع القضايا، ثم حفظه كصورة PNG أو مشاركته عبر خيار مشاركة الملفات في الجهاز. يتلاشى اعتماد التقرير تلقائيًا عند تعديل قضية بعده.

### 2) المهام والتذكيرات
- إضافة مهمة في فئات: قضية تحتاج تصحيحًا، بريد يتطلب ردًا، تذكرة، متابعة، وأخرى.
- عنوان، وصف، رقم قضية/تذكرة اختياري، أولوية، تاريخ مطلوب.
- إظهار اسم من أضاف المهمة بخط صغير وتاريخ الإضافة، مع تعديل المهمة وإزالتها.
- القاضي يضع علامة ✓ **تم الإنجاز**، أو يعيد فتح المهمة؛ ويظهر اسم من أنجزها.
- قائمة مفتوحة ومنجزة والجميع، مع البحث ومؤشر المهام العاجلة.
- إشعار داخل الموقع عند إضافة مهمة أو تعديلها أو إنجازها، وكذلك عند إضافة قضية أو تعديلها أو اعتمادها.

### 3) اختيار الاسم والدخول
- في **وضع المعاينة** (لم يتم ربط Supabase): تظهر قائمة الأسماء بنقرة واحدة *بدون أي كلمة مرور*. تشمل القاضي، كتّاب الضبط الخمسة، وأمينَي السر **يحيى بكري** و**عبد الرحمن الشريف**. اسم «يحيى بكري» مكتوب كما ورد في الطلب؛ الاسم الكامل لم يُؤكد بعد.
- تظهر اسم المستخدم المعيّن محليًا بجانب أعماله في المعاينة، ويمكن تبديله. تحفظ المعاينة التغييرات في **LocalStorage على المتصفح نفسه فقط**، ولا تتزامن بين أجهزة الموظفين؛ وهي *للتجربة ببيانات افتراضية فقط*.
- في **الوضع الفعلي المتصل بقاعدة البيانات**، لا توجد كلمة مرور يتذكرها المستخدم: يختار اسمه ويؤكد الدخول **برابط لمرة واحدة يصل إلى بريده المسجل** (Supabase Passwordless Magic Link)، ثم تُحفظ الجلسة على الجهاز. هذا الشرط ضروري لمعرفة من أضاف أو أنجز بالفعل؛ النقر على الاسم دون تحقق **لا يُثبت الهوية** ولا يحقق أمان البيانات القضائية.
- حساب القاضي `judge`، كاتب الضبط `writer`، أمين السر `secretary`. يستطيع الكاتب والأمين إدخال القضايا والمهام وتعديلها، ويقتصر اعتماد القضايا والتقرير وتعليم المهام «منجزة» على القاضي.

## تشغيل المعاينة دون قاعدة بيانات

1. فك ضغط الملف المرفق وارفع محتوياته إلى GitHub في مستودع جديد (على سبيل المثال `fourth-circuit-work`).
2. من `Settings → Pages → Build and deployment` اختر `Deploy from a branch`، ثم `main` و`/(root)`.
3. افتح رابط GitHub Pages. تظهر قائمة الأسماء مباشرة، اختر اسمًا، ثم جرّب إضافة مهمة أو قضية وفتح التقرير.
4. **تحذير:** عند عدم ربط Supabase لا توجد مزامنة ولا حفظ سحابي. التجربة التي تحفظها على متصفح الموظف **لن** تظهر على جهاز القاضي. لا تدخل بيانات حقيقية في وضع المعاينة.

## تشغيل الحفظ المركزي الفعلي — قاعدة مستقلة

لا تتطلب واجهة GitHub Pages خادمًا، لكنها **لا تصلح وحدها لحفظ بيانات مشتركة**. يزوَّد الموقع بقاعدة Supabase مستقلة بصلاحيات محمية.

1. أنشئ مشروع Supabase جديدًا **مخصصًا لهذا الموقع فقط**، ولا تُعِد استخدام مشاريع توزيع الجلسات أو تطبيقاتك الأخرى.
2. في SQL Editor نفّذ `database/setup.sql` أولًا ثم `database/upgrade_v2.sql` (تضيف المهام والاعتماد والتغييرات). لا تنفذ `upgrade_v2.sql` قبل الملف الأساسي.
3. من Supabase → Authentication → Users أنشئ الحسابات مسبقًا بأسماء المستخدمين وبريد كل منهم. يمكن إنشاؤها إداريًا بكلمات مرور مؤقتة عشوائية لا تُستخدم لاحقًا؛ **واجهة الموقع نفسها لا تسأل عن كلمات مرور**.
4. نفّذ في SQL Editor بعد إنشاء الحسابات (استبدل القيم فقط):

   ```sql
   update public.profiles
      set display_name = 'زياد البابطين', role = 'judge', is_active = true
    where email = 'JUDGE_EMAIL';

   update public.profiles
      set display_name = 'يحيى بكري', role = 'secretary', is_active = true
    where email = 'YAHYA_EMAIL';

   update public.profiles
      set display_name = 'عبد الرحمن الشريف', role = 'secretary', is_active = true
    where email = 'ABDULRAHMAN_EMAIL';
   ```

   وفعّل حسابات كتّاب الضبط بإعداد `role = 'writer'` و`is_active = true` و`display_name` الصحيح. توثيق `profiles.id` يعتمد على بريد الحساب الفعلي، **لا على الاسم المختار في واجهة الدخول**.
5. من Supabase Authentication → URL Configuration ضع رابط موقع GitHub Pages الفعلي في `Site URL` و`Redirect URLs` للسماح بفتح روابط الدخول.
6. حرر `config.js` وضع رابط مشروعك ومفتاح **publishable** المسموح بنشره فقط:

   ```js
   window.APP_CONFIG = {
     supabaseUrl: 'https://YOUR_PROJECT.supabase.co',
     supabasePublishableKey: 'sb_publishable_YOUR_KEY',
     aiEnabled: false
   };
   ```

   **لا تضع `service_role` أو المفتاح السري أو مفتاح OpenAI في GitHub أو في ملفات الواجهة.**
7. ارفع تحديث `config.js` إلى مستودع GitHub. افتح الموقع واختر اسمك، ثم اكتب بريد حسابك المفعّل واضغط «إرسال رابط الدخول»، وافتح الرابط من بريدك. بعد التحقق تبقى الجلسة محفوظة في الجهاز.
8. جرّب ببيانات **افتراضية**: الأمين يضيف مهمة؛ تفتح أنت من جهاز آخر فتظهر مع اسم الأمين؛ ضع علامة الإنجاز؛ جرّب إضافة قضية وتعديلها واعتمادها؛ ثم حفظ صورة التقرير.

> قبل نقل محاضر حقيقية أو أسماء متقاضين إلى خدمة خارجية، يلزم اعتماد الجهة المختصة لبيئة التخزين والمعالجة. موقع GitHub Pages نفسه ملف واجهة عام، لكن بيانات القضايا لا تُوضع داخل المستودع بل في قاعدة البيانات المصرح بها مع RLS.

## الإشعارات والتلخيص

- إشعارات الإضافة والتحديث والإنجاز **داخل الموقع** تتزامن بين الحسابات؛ ويمكن طلب إذن إشعارات المتصفح عند فتح الصفحة.
- إشعارات الدفع إلى الجوال عند إغلاق الموقع **غير مفعلة**؛ تتطلب خدمة Web Push في مرحلة مستقلة.
- `database/noon_reminder.sql` اختياري لتوليد إشعار ظهر اليوم داخل الموقع على Supabase Cron (بعد تفعيله).
- زر «تلخيص بالذكاء الاصطناعي» يحتاج وظيفة `supabase/functions/summarize-minutes/index.ts` ومفتاح API سري على الخادم، وقرارًا مستقلًا بشأن جواز معالجة المحاضر. ما يعمل من دون AI هو «استخراج تحضيري» أولي يحتاج مراجعة، وليس تحليلًا قانونيًا معتمدًا.

## العمل اليومي

- الساعة 10:00 ص: حصر **قضايا الغد فقط** من تقاضي.
- الساعة 11:30 ص: مطابقة جدول الغد وتحديث المستجدات.
- الساعة 12:00 ظهرًا: الاطلاع على التقرير وإصدار الصورة عند الحاجة.
- نحو نهاية الدوام: مطابقة ثانية وإضافة القضايا المؤجلة إلى الغد بعد وقت الظهر.
- صباح يوم الجلسة: تحقق أخير من أي تغيير طارئ في جدول تقاضي.

## ملفات المشروع

- `index.html` و`styles.css`: الواجهة الإدارية الجديدة المتجاوبة.
- `app.js`: القضايا والمهام والصلاحيات والرسائل وإخراج صورة التقرير.
- `config.js`: إعداد الاتصال بالقاعدة (الواجهة خالية من مفاتيح سرية).
- `database/setup.sql`: الجداول الأساسية والصلاحيات.
- `database/upgrade_v2.sql`: المهام، والمراجعات، واعتماد التقرير وإلغاء اعتماده عند تعديل القضايا.
- `database/noon_reminder.sql`: تنبيه الظهر الاختياري.
- `supabase/functions/summarize-minutes/index.ts`: التلخيص الذكي الاختياري على الخادم.
- `manifest.webmanifest` و`assets/favicon.svg`: إعدادات إضافة الموقع للشاشة الرئيسية والأيقونة المجردة غير الرسمية.

### حدود النسخة الحالية

لم يتم نشر النسخة على حساب GitHub لديك أو إنشاء قاعدة جديدة في حسابك في هذه الخطوة. ملفاتها جاهزة للرفع فقط. حفظ الصورة يعمل من المتصفح، أما الحفظ المشترك الحقيقي فسيعمل **بعد** إعداد Supabase كما سبق.
